# 余时 · 产品说明

> 0.3 起以 [随手留下，随时回来](spaces.md) 为准。以下为早期产品规划，周格子、默认重点和完成率导向已被替换。

版本：0.1 产品与实现基线｜更新：2026-09-11

本文定义目标业务，不表示所有条目均已实现。实际交付能力与验证结果以项目 README 为准。

## 1. 产品定位

余时是一款使用 Flutter 开发、数据保存在手机本地的个人时间安排工具。它帮助工作之外仍有多个个人项目、骑行、私事和长期学习计划的人，决定这周投入什么，以及今天从哪里开始。

产品不把清空任务当成唯一目标。核心体验是：打开便知道今天要做什么，执行时减少操作，结束时允许安心停下。

## 2. 产品原则

- **有所选择**：项目可以填写“我为什么在意它”，每周选择少量重点，其他项目保留下一步。
- **适可而止**：任务说明可以填写“做到这里就够了”，让完成有明确边界。
- **允许改变**：缩小、改期、暂停和归档均为正常操作；未完成任务不会全部自动挤到明天。
- **生活同样重要**：学习、骑行、陪伴、休息和私事均能进入安排，不以工作量衡量价值。
- **先记录，再整理**：快速记录只要求一段文字，项目、时间和优先级均可稍后补充。
- **本地优先**：免登录、离线可用；备份由用户保存和管理。

## 3. 导航与首页

主导航为「今天」「本周」「项目」，收集箱与设置从清晰的次级入口进入。快记入口持续可用。

首页保留高级编辑风的大字、重点卡片和留白，采用明亮的纸白与钴蓝配色。今天的具体动作必须先于装饰文案。首页默认呈现一件重点，但不限制每天只能做一件。

首页信息顺序：

1. 日期、轻量问候与「分享今天」入口。
2. 今日重点：具体下一步、所属项目、预计时长、完成边界、一键完成。
3. 固定安排、真实截止事项，以及其他今日任务。
4. 快速记录与今日调整入口。

执行任务无需先点击“开始”或启动计时器。完成后可停下，也可主动再选一件。

## 4. 核心对象

| 对象 | 关键内容 | 业务含义 |
| --- | --- | --- |
| 项目 | 稳定 ID、名称、颜色、为何在意、状态、下一步 | 一个需要持续推进的方向 |
| 任务 | 稳定 ID、标题、项目、状态、预计分钟、完成边界、备注 | 可以实际执行的一步 |
| 排期 | 计划日期、可选时间段、是否固定、重点标记 | 计划何时投入时间 |
| 截止日期 | 日期、可选具体时间 | 外部约束；改排期不会修改截止日期 |
| 重复规则 | 周期、星期、可选结束日期 | 产生独立的安排实例 |
| 重复实例 | 规则 ID、实例日期、完成或跳过状态 | 仅修改本次，不影响整个系列 |
| 周目标 | 周期、目标次数、完成记录 | 例如每周骑行两次；不结转欠账 |
| 进度记录 | 时间、任务 ID、做到哪里、下次起点 | 减少项目切换成本 |
| 设置 | 显示偏好、提醒偏好等 | 随完整备份迁移；设备权限需重新确认 |

所有可合并对象使用稳定 ID。日期与时间的存储和展示必须区分本地日期、具体时间及其时区语义。

## 5. 功能范围与规则

### 快记与收集箱

输入一句话即保存到本地。整理时可转为项目任务、固定安排或重复安排，也可以作为想法保留。临时事项可以直接进入今天。

### 每周规划

先查看工作之外的固定安排、到期事项和可用时间，再选择少量项目成果。建议预留部分空白，用户可以自由调整，不进行强制容量限制。

未选中的项目仍保留状态、进度和下一步。回顾时可继续、暂停、恢复或归档。

### 今天与调整

- 重点任务可以一键完成；其他今日事项仍须可见或可展开查看。
- 调整支持缩小步骤、换一件、改期和今天先放下。
- 未完成任务进入待调整范围；不自动增加第二天负担。
- 固定安排和真实截止事项不能因重点卡片而隐藏。
- 完成记录可撤销；撤销只影响对应任务或重复实例。
- 已归档项目和任务进入单独的归档区，可以恢复。永久删除只在归档区提供，并在确认后级联删除所属任务及完成记录。

### 重复安排与长期目标

固定周期安排按实例记录完成、跳过和改期。修改时明确区分“仅本次”和“整个系列”。按周累计的目标只统计当前周记录，上一周未完成的次数不成为新一周欠账。

### 分享今日计划

首页点击「分享今天」，根据最新计划生成本地 PNG 预览。默认使用与应用一致的纸白、墨蓝和钴蓝风格，不需要调用在线图像生成服务。

用户可取消某项内容、隐藏时间和完成状态。私密任务默认不选中，备注与收集箱不会自动带入。预览中可以看见将被导出的完整内容，再保存图片或打开系统分享面板；不自动发送给任何人。

生成的是当时计划的静态快照，计划发生变化后需要重新生成。第一版不强制水印、不做分享排名。

### 导出与导入

入口：设置 → 数据管理。

- 完整 JSON 备份覆盖项目、任务、排期、重复规则及实例、周目标、完成记录与设置。
- 文件包含 schemaVersion、exportedAt 和稳定记录 ID，名称包含导出日期。
- 导入前校验 JSON 结构、支持版本、类型及关联关系，并展示备份时间与数据数量。
- 默认合并：新增不存在的 ID，相同内容去重；同 ID 内容冲突时保留本地记录，并报告冲突数量。
- 完整替换：先成功创建当前数据的可恢复备份；备份失败则取消替换。
- 数据写入在一个事务中完成；失败回滚到导入前。写入成功后再同步本地提醒。
- 版本不支持、文件损坏或校验失败时，说明原因，保留当前数据。

### 提醒

仅在用户启用提醒时请求系统权限。提醒基于用户明确设置的时间，不为每个未完成任务自动制造催促。导入、改期和删除后更新对应提醒；权限被拒绝时，任务仍可正常使用。

## 6. 数据与平台

- 客户端：Flutter，面向 Android 与 iOS。
- 本地数据库：SQLite；业务界面与数据读写分离。
- 文件备份：JSON，含明确版本与校验逻辑。
- 分享图片：本地排版渲染 PNG；保存与分享使用系统能力。
- 本地提醒：依赖平台权限与通知配置。
- 第一版不要求账号、云同步、多人协作或在线 AI。

本地数据不会自动跨设备同步。删除应用或更换设备前需要保存备份；恢复后提醒权限由新设备重新授予。

## 7. 验收要点

1. 无网络、无账号时可创建项目、记录任务、查看今天并记录完成。
2. 重启后数据仍存在；快速连续操作不会丢失或重复写入。
3. 改计划日期不会修改真实截止日期。
4. 完成或跳过一个重复实例不影响其他实例；周目标不会自动结转欠账。
5. 图片预览与导出内容一致，已隐藏内容不会出现在 PNG 中。
6. 合并导入不重复创建相同 ID；本地冲突内容不被覆盖。
7. 替换前能找到可恢复备份；异常导入不会留下部分写入。
8. 首页一眼能辨认具体任务；大字和留白不会遮蔽固定安排。

## 8. 本次实现策略

先建立可运行的 Flutter 基础、统一视觉与图标、核心页面和本地业务，再逐步接通备份、图片分享和平台能力。尚未接入的功能应明确标识，不用成功提示伪装已完成的系统操作。
