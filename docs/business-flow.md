## 1. 从想法到行动

```mermaid
flowchart TD
    A[随手记一句话] --> B[立即保存到本地收集箱]
    B --> C{整理时是否需要行动}
    C -->|暂时不用| D[保留想法或参考]
    C -->|需要| E[明确可执行的下一步]
    E --> F{如何安排}
    F -->|明确约定| G[固定时间与提醒]
    F -->|项目或一般私事| H[候选任务与可选截止日期]
    F -->|骑行或长期学习| I[重复规则或每周次数目标]
    H --> J[每周规划]
    I --> J
    G --> J
    J --> K[先查看固定安排与到期事项]
    K --> L[估算可用时间并保留空白]
    L --> M[选择少量重点与本周成果]
    M --> N[安排日期或时段]
    N --> O[今天行动]
    G --> O
    O --> P[记录完成与下次起点]
    P --> Q[每周回顾]
    Q --> R{是否继续投入}
    R -->|继续| J
    R -->|暂停| S[保留进度与下一步]
    R -->|不再投入| T[归档]
    S -->|恢复| J
    D -->|决定要做| E
```

临时事项可以直接进入今天。周规划是整理入口，不是每条任务必须经过的审批步骤。

## 2. 今天的操作

```mermaid
flowchart TD
    A[打开应用] --> B[显示今日重点与具体下一步]
    B --> C[同时呈现固定安排和到期事项]
    C --> D{是否有今日重点}
    D -->|有| E[直接行动 无需启动计时]
    D -->|没有| F{用户的选择}
    F -->|选一件| G[从候选任务选取或直接添加]
    G --> E
    F -->|保持留白| Z[结束本次使用]
    E --> H{行动结果}
    H -->|完成| I[一键记录完成]
    I --> J[可选记录下次起点]
    J --> K{是否继续}
    K -->|主动继续| G
    K -->|今天到这里| Z
    H -->|计划变化| L[调整今天]
    L -->|缩小步骤| E
    L -->|换一件| M[保留原任务与进度]
    M --> G
    L -->|改期或放下| N[更新排期 保留真实截止日期]
    N --> Z
    E -.跨日未完成.-> O[进入待调整范围]
    O --> L
```

每日一件重点是展示默认值，不是任务数量上限。未完成不会全部自动滚入明天，真实截止事项仍需持续可见。

## 3. 重复安排与周目标

```mermaid
flowchart TD
    A[创建长期安排] --> B{安排类型}
    B -->|固定周期| C[保存重复规则]
    C --> D[生成对应日期的独立实例]
    D --> E{处理本次}
    E -->|完成| F[记录本次完成]
    E -->|跳过或改期| G[仅修改本次实例]
    D --> H{修改范围}
    H -->|仅本次| G
    H -->|整个系列| C
    B -->|每周几次| I[保存周目标次数]
    I --> J[每次完成产生一条记录]
    J --> K[累计当前周进度]
    K --> L[下一周重新统计]
```

规则和实例分别保存。未达成次数留在历史周记录中，不增加下一周目标。

## 4. 分享今天的计划图片

```mermaid
flowchart TD
    A[首页 分享今天] --> B[读取当前今日计划]
    B --> C[生成本地预览 私密事项默认不选]
    C --> D[选择任务 隐藏时间或完成状态]
    D --> E[重新渲染完整预览]
    E --> F{用户选择}
    F -->|保存图片| G[本地生成 PNG 并保存]
    F -->|分享| H[本地生成 PNG]
    H --> I[打开系统分享面板]
    I --> J[用户选择接收方并发送]
    F -->|取消| K[返回今天]
```

预览不自动包含备注、收集箱和其他日期的安排。生成不依赖在线 AI 服务；图片是静态快照。

## 5. 备份与恢复

```mermaid
flowchart TD
    A[设置 数据管理] --> B{操作}
    B -->|导出| C[读取完整本地数据]
    C --> D[加入版本 导出时间 稳定 ID]
    D --> E[生成并保存 JSON 备份]
    B -->|导入| F[选择备份文件]
    F --> G{格式 版本 关联是否有效}
    G -->|否| H[说明原因 保留当前数据]
    G -->|是| I[预览时间 新增 重复 冲突数量]
    I --> J{确认导入方式}
    J -->|取消| Z[返回数据管理]
    J -->|合并| K[按 ID 去重 冲突保留本地]
    J -->|完整替换| L[先创建当前数据的可恢复备份]
    L --> M{备份是否成功}
    M -->|否| H
    M -->|是| N[准备替换数据]
    K --> O[在单个事务中写入]
    N --> O
    O --> P{写入是否成功}
    P -->|否| Q[回滚到导入前]
    P -->|是| R[更新本地提醒并报告结果]
    R --> S{提醒更新是否成功}
    S -->|否| T[保留已导入数据 提示重试提醒]
    S -->|是| Z
```

文件备份与数据库事务是两个阶段。只有替换前备份成功才进入替换事务；提醒失败不会伪装成数据导入失败。

## 6. 状态与边界

| 动作 | 改变 | 保留 |
| --- | --- | --- |
| 完成任务 | 当前任务或当前实例的完成状态 | 项目、历史记录 |
| 改期 | 计划日期或时间段 | 真实截止日期 |
| 今天放下 | 今日排期或重点选择 | 任务内容、已有进度 |
| 暂停项目 | 项目参与规划的状态 | 历史、下一步 |
| 归档 | 活跃列表中的展示状态 | 可查询的历史数据 |
| 撤销完成 | 对应任务或实例的状态 | 其他任务与实例 |
| 合并导入 | 新 ID 对应的数据 | 本地冲突记录 |
| 替换导入 | 事务成功后的全部业务数据 | 替换前可恢复备份 |
